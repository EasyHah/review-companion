# 核心行为路径

目标是让用户不打开文件也能看懂一条行为从起点到终点，以及本次改变了什么。图和解释直接在对话交付，不创建面板、候选选择器或结构化图存储。

复用当前讨论、已给出的功能总览与固定提交范围。用户已经指定行为就直接展开；只有范围不明确时才简短推荐一条路径并说明理由，等待用户选定。不要强制每次经过“推荐→确认”。

读取支持路径的固定源码。已有回顾时可用 read_fixed_evidence；未修改模块可按仓库规则通过只读 Git 工具读取同一固定提交，不能把当前工作区当成历史证据。只加入串通行为必需的原有环节，不把静态依赖当作已确认的运行调用。默认不检索说明文档。

用对话内可渲染的简单 Mermaid 流程图表达主流程；宿主不能渲染时使用可读的文本箭头图，不要求用户另开服务。节点写行为与模块，箭头说明交接的条件、数据或控制关系；清楚区分本次改动与原有环节。节点保持可读，改动前后差异可紧接图逐项说明，但图与相邻解释合起来必须独立讲清完整路径。

只补充本次直接涉及的异常或条件分支。对未经证实的关系明确说明，不用确定连线掩盖推测。注明省略范围，引用支持关键环节的具体固定代码位置。行为图不是风险判定，也不表示其他路径已覆盖。

不调用 set_file_risks、不改变已回顾进度；用户进一步要求风险核实时再使用分支风险分析。不要为生成图调用插件的旧版 set_behavior_path 或 set_risk_overview。完成一条路径后结束，继续哪条由用户决定。
