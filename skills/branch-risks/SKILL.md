# 分支风险分析

直接在对话交付分析，不创建风险总览页、分析任务或额外选择流程。默认用当前模型，用户只要风险时不自动讲解全部文件或画行为图。

先确认比较范围和实际仓库。已有回顾记录时读取并核对固定 base_sha/target_sha，使用 list_review_files 分页获取真实 file_id。用户要求当前分支时核对当前 ref，不能沿用已过期的固定比较。未明确范围且无法从上下文判断时只问必要的问题。

按功能筛选值得重点核实的改动，读取固定代码及必要调用方，必要时比较前后实现。文件大、涉及核心模块只是筛选线索，不构成风险。只重点报告本次引入或放大的问题，无关旧问题不混入。Markdown 等说明文档不作为回顾对象，但适用仓库规则仍须遵守。

每条疑点在对话说清：属于哪个功能、具体代码位置和证据、何种条件下有什么后果、为何与本次改动有关、还缺哪项验证。没有运行过就不能称已复现；证据不足的推断明确标为待核实。先给重点，深度由追问承担。没有疑点时说明实际核实范围与限制，不宣称整个分支安全。

有回顾伴随工具时，分析交付后把对应文件高亮：重读最新 version，用 `set_file_risks(review_id,expected_version,updates=[{file_id,notes:[短说明]}])`。每条 notes 最多300字，每文件最多5条，只保留定位所需的一两句，例如“L42–48：保存失败仍返回成功；上层兜底待核实”。完整证据和验证过程留在对话，不再保存另一份报告。file_id 必须来自该固定比较，不靠文件名猜。

一次更新只改传入文件；未核实的文件保留原标记。更新前看已有 risk_notes，保留仍成立的线索；仅明确排除或解决时用 notes=[] 清除对应文件，不因这次未发现新问题而清空所有标记。同一文件属于多个功能时由插件自动在各组显示。同步失败简短说明，保留对话分析；版本冲突重读核对，不盲目覆盖。风险标记不改变 reviewed、短结论或分组。

独立使用本技能时不依赖插件：工具不可用就交付对话分析，不要求用户安装或建立新流程。用户要求同步到插件但没有对应记录时，复用回顾伴随的固定范围与轻量功能分组能力，不逐文件讲解。结束后等待用户选择疑点深入，不自动推进。
